# FRAME — сообщество фотографов и моделей

Веб-платформа, где фотографы, модели и участники съёмочных команд находят друг друга, собирают портфолио, публикуют объявления о съёмках и договариваются о сотрудничестве во встроенном чате.

> Рабочее название **FRAME** и логотип меняются в двух местах: `src/config/brand.ts` и `src/components/brand/logo.tsx`.

## Что реализовано

| Раздел | Возможности |
| --- | --- |
| **Аккаунты** | Регистрация по почте и паролю с выбором типа профиля (фотограф / модель / оба), подтверждение почты, вход, восстановление пароля, выход, смена почты и пароля, удаление аккаунта вместе с файлами. При первом входе — экран заполнения профиля и загрузки аватара |
| **Профиль** | Имя, адрес профиля, аватар, обложка, город, описание, специализации, опыт, доступность, форматы сотрудничества, соцсети. Возраст, параметры модели и контакты — только по желанию пользователя и с настройкой видимости |
| **Портфолио** | Работы из нескольких фото (загрузка с перетаскиванием, сжатие в браузере, удаление EXIF/геолокации), название, описание, категория, дата, теги, отметка участников съёмки, порядок работ и фото, обложка, публикация/скрытие, редактирование и удаление. Лента с masonry-сеткой, фильтрами и сортировкой, страница работы с полноэкранным просмотром |
| **Поиск** | Каталоги «Найти фотографа» и «Найти модель» по реальным профилям: поиск по имени и ключевым словам, город, тип, специализация, категория работ, опыт, доступность, формат, теги; сортировка по релевантности, активности, дате; «Загрузить ещё»; пустые состояния и сброс фильтров |
| **Проекты и съёмки** | Объявления (тип съёмки, кого ищут, формат, условия участия, отдельно — условия использования снимков, требования, количество мест, обложка), фильтры, отклики с сообщением автору, принятие/отклонение/отзыв, статусы проекта |
| **Чат** | Личные диалоги (ровно один на пару пользователей), сообщения в реальном времени (Supabase Realtime), отметки «прочитано», счётчики непрочитанного, поиск диалогов, всплывающие уведомления, жалоба на сообщение, блокировка. На телефоне — отдельные экраны списка и переписки |
| **Социальное** | Лайки, избранные работы и люди, уведомления (сообщения, отклики, ответы на отклики, статусы проектов, лайки, отметки в работах) с настройками и обновлением в реальном времени |
| **Админка `/admin`** | Статистика (переписки — только агрегированно), поиск пользователей по имени и почте (почта видна только администраторам), блокировка, роли, жалобы со снимком содержимого, скрытие и удаление работ и объявлений (вместе с файлами), управление категориями |
| **Безопасность** | RLS на всех таблицах, закрытые для записи служебные колонки, проверки ролей в функциях БД и на сервере, ограничения частоты действий, лимиты размера и типа файлов, защита от open redirect, заголовки безопасности, жалобы на фото без разрешения, правило 18+ |

Сквозные тесты (Playwright) проходят весь сценарий из критериев готовности — см. [Тесты](#тесты).

## Стек

- **Next.js 16** (App Router, Server Components, Server Actions, Turbopack) + **TypeScript**
- **Tailwind CSS 4**, компоненты в стиле shadcn/ui на **Radix UI**, иконки **lucide**
- **Supabase**: PostgreSQL + Row Level Security, Auth, Storage, Realtime
- **Zod 4** — валидация на сервере (и типы форм)
- **Playwright** — сквозные тесты

### Архитектура

```
Браузер ──► Next.js (src/proxy.ts обновляет сессию и закрывает /dashboard, /admin)
   │            │
   │            ├─ Server Components: чтение данных от имени пользователя
   │            └─ Server Actions (src/actions): валидация Zod → запрос в Supabase
   │
   ├─► Supabase Storage — загрузка фото напрямую из браузера (только в папку <user_id>/)
   └─► Supabase Realtime — сообщения, отметки о прочтении, уведомления

Supabase (PostgreSQL)
   ├─ RLS-политики на каждой таблице: что видит и меняет каждый пользователь
   ├─ привилегии на колонки: роль, блокировка, счётчики, владелец — недоступны для записи
   ├─ функции (RPC): поиск, диалоги, отклики, жалобы, админ-действия — с проверкой прав
   └─ триггеры: уведомления, счётчики, обложки работ, ограничение частоты
```

Сервисный ключ Supabase (`service_role`) приложению **не нужен**: все запросы выполняются от имени пользователя, а права проверяет база данных. Даже если обойти интерфейс и обратиться к API напрямую, политики RLS не позволят прочитать чужую переписку или изменить чужой контент.

## Быстрый старт (локально)

Нужны **Node.js 20.9+** и **Docker** (для локального Supabase).

```bash
npm install
npx supabase start          # поднимает Postgres, Auth, Storage, Realtime, почтовый ящик; применяет миграции и seed.sql
cp .env.example .env.local
```

Заполните `.env.local` значениями из вывода `npx supabase start` (их же покажет `npx supabase status`):

```env
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key / Publishable key>
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

```bash
npm run dev                 # http://localhost:3000
```

- Письма (подтверждение почты, восстановление пароля) приходят в локальный ящик: http://127.0.0.1:54324
- Supabase Studio: http://127.0.0.1:54323
- Пересоздать базу с миграциями и демо-данными: `npx supabase db reset`

### Первый администратор

Зарегистрируйтесь через сайт, затем выдайте себе роль (ключ `service_role` — из `npx supabase status`, используется только этим скриптом):

```bash
SUPABASE_SERVICE_ROLE_KEY=<service_role key> npm run make-admin -- <ваш_адрес_профиля_или_почта>
# роль модератора: ... npm run make-admin -- <username> moderator
```

Или SQL-запросом в Supabase Studio: `update public.profiles set role = 'admin' where username = '<username>';`

Ссылка на админку в навигации не показывается — она есть только в меню пользователя у администраторов и модераторов: `/admin`.

## Развёртывание

### 1. Проект Supabase

1. Создайте проект на [supabase.com](https://supabase.com/dashboard).
2. Примените миграции:
   ```bash
   npx supabase login
   npx supabase link --project-ref <project-ref>   # Project Settings → General → Reference ID
   npx supabase db push
   ```
   Без CLI: выполните файлы из `supabase/migrations/` по порядку в SQL Editor.
3. **Authentication → URL Configuration**: Site URL — адрес сайта (например, `https://frame.example`), в Redirect URLs добавьте `https://frame.example/**`.
4. **Authentication → Email Templates**: вставьте шаблоны из `supabase/templates/` (Confirm signup, Reset password, Change email address). Ссылки в них ведут на `/auth/confirm` с `token_hash`, поэтому подтверждение работает, даже если письмо открыто на другом устройстве. Со стандартными шаблонами тоже будет работать, но только в том же браузере, где начата регистрация.
5. **Authentication → SMTP Settings**: подключите свой SMTP — встроенная отправка Supabase предназначена только для тестов и сильно ограничена по количеству писем.
6. Демо-данные (`supabase/seed.sql`) в боевой проект добавлять не обязательно. Если нужно наполнить интерфейс — выполните файл в SQL Editor; удалить демо-аккаунты: `delete from auth.users where email like '%@demo.frame.local';`

### 2. Хостинг Next.js (например, Vercel)

Импортируйте репозиторий и задайте переменные окружения:

| Переменная | Где взять |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Project Settings → API → Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase → Project Settings → API Keys → `anon` public (или Publishable key) |
| `NEXT_PUBLIC_SITE_URL` | публичный адрес сайта, тот же, что Site URL в Supabase Auth |

`SUPABASE_SERVICE_ROLE_KEY` на хостинг **не добавляйте** — он не нужен приложению.

Подойдёт любой хостинг с Node.js 20.9+: `npm run build && npm start`.

## Тесты

```bash
npm run typecheck
npm run lint
npm run test:e2e
```

Сквозные тесты запускаются против **локального** Supabase и запущенного приложения (`npm run dev` или `npm run build && npm start`). Им нужны переменные (кроме значений из `.env.local`):

```bash
SUPABASE_SERVICE_ROLE_KEY=<service_role из npx supabase status> \
MAILPIT_URL=http://127.0.0.1:54324 \
npm run test:e2e
```

Тесты используют сервисный ключ только для создания тестовых пользователей и проверок; не запускайте их на боевом проекте.

| Файл | Что проверяет |
| --- | --- |
| `e2e/mvp-scenario.spec.ts` | Критерий готовности MVP через интерфейс: регистрация фотографа и модели с подтверждением почты, профиль и аватар, загрузка и публикация портфолио, поиск, «Написать» (повторно открывается тот же диалог), сообщения в реальном времени и отметки о прочтении, отклик на объявление с сообщением в чат, принятие отклика и уведомления, избранное, админка: жалоба (виден только текст обжалованного сообщения), запрет открыть переписку, скрытие работы, блокировка пользователя |
| `e2e/security.spec.ts` | Права доступа напрямую через API: гость не видит приватных данных, нельзя выдать себе роль, чужие работы не редактируются, подмена владельца и отправителя невозможна, файлы только в свою папку и только изображения, переписка видна только участникам, администратор не читает сообщения, блокировки, бан, ограничение частоты, удаление аккаунта |
| `e2e/account.spec.ts` | Восстановление пароля по ссылке из письма, редактирование профиля и видимость контактов, удаление аккаунта вместе с файлами |

## Безопасность и приватность

- **RLS** включён на всех таблицах; права выдаются явно (принцип «всё запрещено, пока не разрешено»).
- **Колонки**: пользователь может менять только «свои» поля профиля; роль, блокировка, счётчики лайков и откликов, модерация, владелец записи — закрыты на уровне привилегий PostgreSQL. Владелец и отправитель подставляются из `auth.uid()`.
- **Переписка**: читать и писать могут только участники диалога; модераторы видят только текст сообщения, на которое пожаловались (снимок в жалобе).
- **Приватные данные** (дата рождения, параметры, контакты, настройки) лежат в отдельной таблице `profile_private`, доступной только владельцу. Наружу они попадают через функцию `profile_public_details` и только если пользователь включил показ. Параметры моделей не участвуют в публичном поиске.
- **Файлы**: бакеты `avatars` (5 МБ) и `media` (15 МБ), только JPEG/PNG/WebP, запись только в папку `<user_id>/`. Перед загрузкой изображения сжимаются в браузере, метаданные (включая геолокацию) удаляются.
- **Спам**: ограничения частоты в базе (сообщения, работы, проекты, отклики, жалобы, новые диалоги) плюс встроенные лимиты Supabase Auth.
- **Админка**: роль проверяется в `requireModerator()` на сервере при каждом запросе и повторно внутри функций БД `admin_*`; для остальных `/admin` отвечает 404.
- **Блокировки**: пользователь может заблокировать другого (переписка невозможна в обе стороны); администрация может заблокировать аккаунт — его профиль и контент скрываются, публиковать и писать он не может.
- **Возраст**: платформа рассчитана на пользователей 18+ (подтверждение при регистрации, `brand.minAge`). Если планируется доступ для несовершеннолетних, нужны отдельные правила общения, модерация и юридическая проверка.
- Документы (`/terms`, `/privacy`, `/consent`, `/rules`) — **шаблоны**; перед запуском проверьте их с юристом и укажите реквизиты оператора персональных данных.

## База данных

| Таблица | Назначение |
| --- | --- |
| `profiles` | публичный профиль (1:1 с `auth.users`), роль и блокировка |
| `profile_private` | приватные данные, контакты, настройки уведомлений, согласия |
| `categories` | категории съёмки и специализации (управляются в админке) |
| `portfolio_items` | работы портфолио |
| `portfolio_images` | фотографии работы с порядком |
| `portfolio_tags` | теги работ |
| `portfolio_credits` | участники съёмки (пользователь или имя) и роль |
| `projects` | объявления о съёмках |
| `project_applications` | отклики (один на пользователя и проект) |
| `conversations`, `conversation_members`, `messages` | диалоги, участники с отметкой прочтения, сообщения |
| `likes`, `favorites` | лайки; избранные работы и люди |
| `notifications` | уведомления (группируются, пока не прочитаны) |
| `reports` | жалобы со снимком содержимого |
| `user_blocks` | блокировки между пользователями |

После изменения схемы обновите типы: `npm run db:types` (нужен запущенный локальный Supabase).

## Языки интерфейса

Все тексты — в `src/i18n/dictionaries/ru.ts`. Чтобы добавить язык: создайте словарь с типом `Dictionary` (TypeScript подскажет недостающие ключи), добавьте его в `src/i18n/dictionaries/index.ts` и код языка в `src/i18n/config.ts`. Язык выбирается по cookie `locale`; названия категорий переводятся через поле `translations` в таблице `categories`.

## Демо-данные и изображения

`supabase/seed.sql` создаёт 12 демо-профилей, работы и проекты с фотографиями с Unsplash (только для наполнения интерфейса при разработке; у демо-аккаунтов нет пароля, войти в них нельзя). Главный экран показывает популярные работы участников; пока их меньше трёх — изображения из `src/config/hero.ts`.
